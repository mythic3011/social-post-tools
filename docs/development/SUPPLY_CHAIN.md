# Supply-chain policy

Social Post Tools uses mise as the single toolchain entrypoint and keeps package-manager lockfiles for project dependencies.

## Toolchain

`mise.toml` exact-pins the project tools:

```toml
[tools]
node = "24.20.0"
python = "3.13.15"
"aqua:astral-sh/uv" = "0.12.5"
```

The uv registry entry uses the mise aqua backend. Aqua-backed installations can use upstream checksum/signature/provenance metadata, including GitHub Artifact Attestations where the registry declares them.

`minimum_release_age = "7d"` is also configured. Exact reviewed pins are not silently moved by this policy; it protects future fuzzy resolution and intentional upgrades from consuming a just-published release immediately.

## GitHub Actions

Third-party actions are referenced by immutable commit SHA instead of mutable major tags. Comments retain the human-readable release tag.

The shared `.github/actions/setup-toolchain/action.yml` uses:

- `jdx/mise-action` pinned to the v4.3.0 commit;
- mise binary `2026.9.5`, selected after its release-age window;
- mise installation verification supplied by the action;
- `npm ci --ignore-scripts --no-audit --no-fund`;
- `uv sync --locked`.

The same local action is reused by CI, Pages, and Worker validation so tool setup cannot drift across workflows.

## Lockfiles

- `package-lock.json` pins npm dependency versions and integrity values.
- `uv.lock` pins the Python test dependency graph and wheel hashes.
- `mise.lock` pins tool artifacts and their available checksums/provenance. It must be generated by mise itself, not handwritten.

When changing a tool version:

```bash
mise use <tool>@<version>
mise lock --platform linux-x64,macos-arm64,windows-x64
mise install --locked
mise run check
```

Review the lockfile diff together with the version bump.
